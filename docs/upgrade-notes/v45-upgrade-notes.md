# Hoist Core v45 Upgrade Notes

> **From:** v44.x → v45.0.0 | **Released:** unreleased | **Difficulty:** 🟢 LOW

## Overview

Hoist Core v45 moves agent docs and tooling to Hoist Docs, and adds a server-side store for Hoist
Blueprints. Most apps need the version bump, a hoist-react upgrade, and two small build edits.

The app-level impacts are:

- **Requires hoist-react 91** - Agent docs for hoist-core 45 come only from Hoist Docs, which an app
  gets with hoist-react 91.
- **`installHoistCoreTools` removed** - The task fails on this release, because its artifact is no
  longer published.
- **Three new tables for blueprint storage** - `xh_blueprint`, `xh_blueprint_publish` and
  `xh_blueprint_personalization`. Apps that run `dbCreate: 'update'` get them at startup.

## Prerequisites

Before starting, ensure:

- [ ] **The app is on hoist-core v44.x** - see the [v44 upgrade notes](./v44-upgrade-notes.md).
- [ ] **Database access**, if the app does not run `dbCreate: 'update'`, to create the new tables.

## Upgrade Steps

### 1. Bump `hoistCoreVersion`

**File:** `gradle.properties`

Before:
```properties
hoistCoreVersion=44.1.0
```

After:
```properties
hoistCoreVersion=45.0.0
```

### 2. Upgrade hoist-react first

Hoist Core 45 requires `hoist-react >= 91`. On an earlier hoist-react, the agent has no hoist-core
reference. Upgrade hoist-react before this release.

### 3. Remove the hoist-core tools snippet and MCP entry

**Files:** `build.gradle`, `.mcp.json`

Remove the `installHoistCoreTools` snippet from `build.gradle`, and the `hoist-core` entry from
`.mcp.json`. Point `.mcp.json` at `@xh/hoist-docs` instead, as the Hoist Docs README describes.

### 4. Create the blueprint tables, if the app manages its schema

Apps that run `dbCreate: 'update'` get the new tables at startup and can skip this step.

Hoist Core maps the tables at startup, whether or not the app enables blueprint storage. So an app
that runs `dbCreate: 'validate'` must create them before it starts.

For other apps, review and run the following SQL, modified as needed for your database. It is
written for MySQL with InnoDB.

```sql
CREATE TABLE xh_blueprint (
    id BIGINT NOT NULL AUTO_INCREMENT,
    token VARCHAR(255) NOT NULL,
    name VARCHAR(255) NOT NULL,
    description LONGTEXT NULL,
    owner VARCHAR(50) NOT NULL,
    writers LONGTEXT NOT NULL,
    readers LONGTEXT NOT NULL,
    draft LONGTEXT NOT NULL,
    draft_version BIGINT NOT NULL,
    pending_renames LONGTEXT NOT NULL,
    published_version INT NULL,
    copied_from_token VARCHAR(255) NULL,
    copied_from_version BIGINT NULL,
    copied_from_kind VARCHAR(7) NULL,
    date_created DATETIME NOT NULL,
    last_updated DATETIME NOT NULL,
    last_updated_by VARCHAR(255) NULL,
    PRIMARY KEY (id),
    CONSTRAINT uk_xh_blueprint_token UNIQUE (token)
) ENGINE=InnoDB;

CREATE INDEX idx_xh_blueprint_token ON xh_blueprint (token);

CREATE TABLE xh_blueprint_publish (
    id BIGINT NOT NULL AUTO_INCREMENT,
    blueprint_id BIGINT NOT NULL,
    publish_number INT NOT NULL,
    content LONGTEXT NOT NULL,
    renames LONGTEXT NOT NULL,
    note LONGTEXT NULL,
    published_by VARCHAR(50) NULL,
    date_created DATETIME NOT NULL,
    PRIMARY KEY (id),
    CONSTRAINT uk_xh_blueprint_publish_number UNIQUE (blueprint_id, publish_number),
    CONSTRAINT fk_xh_blueprint_publish_blueprint FOREIGN KEY (blueprint_id) REFERENCES xh_blueprint (id)
) ENGINE=InnoDB;

CREATE INDEX idx_xh_blueprint_publish_blueprint ON xh_blueprint_publish (blueprint_id);

CREATE TABLE xh_blueprint_personalization (
    id BIGINT NOT NULL AUTO_INCREMENT,
    blueprint_id BIGINT NOT NULL,
    username VARCHAR(50) NOT NULL,
    preset VARCHAR(255) NOT NULL,
    ops LONGTEXT NOT NULL,
    publish_version INT NOT NULL,
    date_created DATETIME NOT NULL,
    last_updated DATETIME NOT NULL,
    PRIMARY KEY (id),
    CONSTRAINT uk_xh_blueprint_personalization UNIQUE (username, blueprint_id, preset),
    CONSTRAINT fk_xh_blueprint_pers_blueprint FOREIGN KEY (blueprint_id) REFERENCES xh_blueprint (id)
) ENGINE=InnoDB;

CREATE INDEX idx_xh_blueprint_pers_blueprint ON xh_blueprint_personalization (blueprint_id);
```

> **Note:** Column types vary by database. For SQL Server, use `NVARCHAR(MAX)` for `LONGTEXT`,
> `DATETIME2` for `DATETIME` and `BIGINT IDENTITY(1,1)` for the `id` columns. For PostgreSQL, use
> `TEXT`, `TIMESTAMP` and `BIGINT GENERATED BY DEFAULT AS IDENTITY`. The JSON columns must hold
> large text, because a blueprint can exceed the 64 KB of a MySQL `TEXT` column.

### 5. Enable blueprint storage, if the app uses it

Blueprint storage is off by default, and needs no action from apps that do not use it. To use it,
set `enabled` in the `xhBlueprintConfig` soft config, and set `createRoles` to the roles that may
create blueprints. See [`blueprints.md`](../blueprints.md).

An app service named `BlueprintService` collides with Hoist Core's, because Grails resolves services
by bean name. Rename such a service before upgrading.

## Verification Checklist

- [ ] The app builds and starts on hoist-core 45.0.0, with hoist-react 91.
- [ ] `build.gradle` has no `installHoistCoreTools` snippet, and `.mcp.json` has no `hoist-core`
  entry.
- [ ] The `xh_blueprint`, `xh_blueprint_publish` and `xh_blueprint_personalization` tables exist.
- [ ] If the app uses blueprints, `xhBlueprintConfig.enabled` is true and its `createRoles` are set.
